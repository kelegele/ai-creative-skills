# 输入归一化(gzh-typeset)

> 目的:gzh-typeset 默认收 gzh-longform 的 `article.md`(Markdown)。当用户给的排版源不是 Markdown 时,先归一化成 Markdown 草稿,再进排版流程。
> 原则:归一化只**重建结构**,不改原文文字;结构拿不准的段落原样保留,标注「⚠️ 结构待确认」交给用户。

## 支持的输入与转法

| 输入 | 转法 | 工具 |
|---|---|---|
| `.md` | 直接用 | 无 |
| `.docx` | 抽段落文本 → 按 Word 标题样式加 # 前缀 → md 草稿 | `scripts/extract_docx.py --headings` |
| `.pdf` | 读文本 → 按行首 `## / ###` 推断标题,段落合并 → md 草稿 | 手动(agent 读) |
| `.txt` / 纯文本 | 按标题启发式:行短且无句末标点 = 候选标题;空行分节 → md 草稿 | 手动(agent 读) |
| 网页富文本 | 复制正文 → 按标题启发式 → md 草稿 | 手动 |

## 归一化规则

1. **docx**:`extract_docx.py --headings` 输出;标题样式(H1/H2/H3)直接映射 #/##/###;正文段落原样。
2. **标题启发式**(pdf/txt/富文本):行首 `#` 保留;无标记时,满足「长度 < 30 字 + 不以句号/逗号结尾 + 独立成段」判为标题,加 `##`;拿不准的标 ⚠️。
3. **引用块**:原文以「> 」或「引用」开头的段,归一化成 `> ` 块(对应排版里的引用框)。
4. **列表**:原文 `-` / `1.` 开头保留;富文本粘贴丢失列表符的,按「每行一句 + 空行分隔」重建,不硬套列表符。
5. **图片**:`![说明](路径)` 保留;富文本只有 `<img>` 的,转成 `![说明](原src)`,路径待用户确认。
6. **代码/命令**:围栏 ``` 保留;行内 `` ` `` 保留(排版有代码样式)。

## 归一化后

- 输出 md 草稿给用户**确认结构**(章节划分、标题层级、引用/列表归属)再进排版。
- 确认后的 md 走 gzh-typeset 正常工作流(第 0 步参数 → 标点全角 → 基准段先行 → 批量)。
