# 口播稿调稿经验库(tuning-lessons)

> 来源:2026-08-14「AI 烧了钱效率没涨,问题出在哪?」口播稿调稿实录(9 轮,用户主导)。
> 每条经验都附**用户原话 / 原稿 vs 改后 / 结论**,让后续调稿有据可依。

## 一、口语化与对话感

### L1 开头用「事实钩子」,不用概念引入
- 用户原话:「换成事实开头:『很多人烧了几千块 Token,效率一点没涨,钱去哪了?』」
- ❌ 原稿:「最近有个词反复出现:不可能三角。成本、智能、性能——这三样,你不可能全都要。」
- ✅ 改后:「很多人烧了几千块 Token,效率一点没涨,钱去哪了?」
- 结论:口播开头要「具象事实 + 悬念问题」,让听众立刻对号入座;"有个词叫 XX"是论文开场,不是口播。

### L2 口播稿的验收标准 = 读一遍转文字,要像平时说话
- 用户原话:「我试着读了一段,然后转为文字,这个东西和你的稿子还是有一些出入。你的稿子还是不够口语化。」
- 用户转写实例:「你有没有发现,身边越来越多的人在用这个 AI 去工作?那很多人用 AI 怎么就烧了几千块钱的 token,但是他们的这个效率一点都没涨…」
- 结论:口播稿不能"语法正确"就算过,要**允许口语填充词**(这个/那个/就是/然后/那么/所以说/呢/啊)、冗余、补述。最硬检验:自己读一遍转文字,转写结果越接近平时说话越好。

### L3 杀掉「书面缩写」,哪怕只有三个字
- 用户原话:「正常人说话很少会蹦出三个词『真不是』,没人说话会这样子」
- ❌:「问题在模型不够聪明吗?真不是。」
- ✅:「那你说,问题真的出在模型身上吗?其实不是。」
- 结论:书面缩写(真不是/即/亦/便)在口播里全部违和;「其实不是」「真的没有」这类自然口语才像人。

### L4 对话感 = 面对面跟一个人讲,不是对空气念
- 用户原话:「没有对话感你懂吗…就是让这篇稿子的语气、内容看上去就是面对面主播在跟某个人讲的东西。在跟人沟通的过程中,会停顿,会有各种各样的语气,会做一些停顿,或者做一些语气词,或者是跟人确定的一些用词」
- 手法:开场叫住听众(「你有没有发现」)、反问确认(「你是不是用得就越勤?」)、抛问题留白(「钱去哪了?(停2秒)」)、口语引导(「你一听就明白」)。
- 结论:对话感不是加几个"嗯/啊",是让稿子全程像主播在跟你确认、问你、等你反应。

### L5 伪专业词比真专业词更伤人
- 用户原话:「还有一些词汇不会再口语中使用的也检查下」
- 杀掉的词:边际成本错配 → 账算的方式不一样;效率悖论 → 越用越勤越勤越贵;系统摩擦 → 钱花在返工上;买断制/租赁制 → 一次性买下来/按用量租;可用性的拐点 → 能用的那道坎;持续堆基建 → 砸钱建机房加服务器;系统性提升 → 把整个系统做上去;一味追求 → 只顾着追;一起迭代 → 一起往前跑。
- 结论:真专业词(Harness/Agent/Token)带解释保留;伪专业词(书面语伪装成概念)全杀——小白听不懂还显得端。

## 二、节奏标注

### L6 口播稿要加节奏标注(念稿人的"演奏谱")
- 用户原话:「口播稿除了文本以外,还要加上一些标注。我不记得是什么标注了,反正就是节奏的一些标注。」
- 行业背景:朗读/播音符号标记(16 符号体系,⌒∨▲▽﹏→↑↓),主播提词器版用括号中文。
- 本项目精简标注体系:
  - `(停顿)` 换气留白 / `(停2秒)` 长停顿抛问题后
  - `(放慢)` / `(加快)` 语速
  - `(加重)` 重音关键结论 / `(轻声)` 低语悬念
  - `(笑)` / `(反问)` 语气表情
  - `…` 拖长音 / `↗` `↘` 升降调
- 结论:同一句话不同停顿重音,效果完全不同;标注是给念稿人的演奏谱,生成稿必带。

## 三、标题

### L7 先读目的仓库已发标题校准风格,不要随手写
- 用户原话:「都不好,请深度挖掘自媒体好标题」(否掉 AI 随手 3 个候选)
- 对照已发飞栗标题:harness「AI 一改项目就乱?你缺的不是提示词」、b-end「老板让加AI,先分清这3类产品形态」、goal「/goal 给AI下任务别再说步骤了」。
- 结论:飞栗标题 = 痛点场景 + 人话动作 + 冷静;禁「警告!」营销腔(与冷静陈述者冲突)。用公式库(如 dbs-xhs-title)挖题时,公式结构可留,表达换目的仓库腔。

### L8 纯悬念问句 > 给半个答案
- 用户拍板:「AI 烧了钱效率没涨,问题出在哪?」(公式 #14 变体:不想要结果的最根本原因)
- 被否:「AI 越用越贵?你缺的不是更好的模型」(与已发「你缺的不是提示词」同句式、有系列感,但钩子弱)
- 结论:标题宁可**只问问题、不给半个答案**,答案全留正文;「你缺的不是 X」这类给一半答案的句式,悬念不足。

## 四、品牌风格

### L9 口播稿要和卡片/长文是"同一个飞栗在说话"
- 用户原话:「再看看以往的稿子,再看看品牌风格,稿子加上品牌风格」
- 落地:专业词具体化建可信(「用这个 AI」→「用 Claude Code、Codex 这些」)、收尾金句打磨(「真正拉开差距的,不是哪个模型更聪明,而是谁能让模型、Agent、整个系统,一起往前跑。」)、互动钩子贴品牌惯例(「评论区聊聊:你为了用 AI,烧过多少冤枉钱?」)。
- 结论:换媒介不能换人设;口语化不能滑向嗨腔,冷静陈述底子守住。

## 五、内容优先

### L10 先审"说什么",再审"怎么说"
- 用户原话:「文章内容还是之前的吧 你在生成稿子的时候没有审过内容吗?没有一些内容建议吗?」
- 教训:前 7 轮全在改表达(口语/标注/品牌),内容本身没审。内容审核发现:
  1. 选题核心「不可能三角」框架在改标题后丢了 → 请回开头,三个错配挂回三角(追智能时另外两角付出代价)
  2. DeepSeek 段太虚 → 落到一手素材实锤(V4-Flash 无自家 Agent / 官方推荐配 Codex / Harness 团队研发中)
  3. 虚构数字「烧了几千块」→ 改泛化/举例口径,不当真实统计
- 结论:口播稿也是内容产品,"说什么"优先于"怎么说";一手素材有实锤必须用;框架(选题灵魂)不能因表达改动而丢。

### L11 框架是用户定的,素材只是填肉
- 用户定稿基准 v10(80 分 + 已录音)保留了:三角框架、三个错配挂回三角、DeepSeek 实锤。
- 结论:改表达不改骨架;用户认可的分析和框架,后续轮次继续沿用。

## 调稿流程经验

### L12 调稿节奏:出完整版让用户挑刺,不反复抛候选
- 用户对候选多轮未拍板 → AI 直接应用 Top 1 出完整版,让用户对整篇开火。
- 结论:调稿不要一直抛选择题;一版"定稿感"完整稿 + 让用户指哪里不对,才是"调"的节奏。

### L13 每轮记录:用户原话 / 改动点 / 原因
- 全程 9 轮调稿记录(要求原话、改动点、原因推断),成为本经验库的原料。
- 结论:调稿必须逐轮记录,这是沉淀 skill 的原料;用户原话是最可靠的依据,不臆测。
