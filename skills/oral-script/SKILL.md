# oral-script 口播稿创作与调稿

通用口播稿 skill:从选题/素材生成**念稿用逐字稿**(播客 / 视频口播两渠道通用),**带节奏标注**,可逐轮调稿到定稿。读目的仓库 `AGENTS.md`/`CLAUDE.md` 取人设;不依赖第三方 skill。

调稿经验库在 `references/tuning-lessons.md`(13 条,附用户原话),生成与调稿前先读。

## 工作流

### 第 0 步 运行参数 + 读人设

问用户(存为本次运行变量):
- **OUTPUT_DIR** — 默认 `Content/YYYYMMDD-<slug>/`(今日创建日),用户可改
- **目标时长**(分钟)— 决定字数(中文口播约 200-260 字/分钟)
- **渠道** — 播客 / 视频口播(两者共用同一逐字稿)

读目的仓库 `AGENTS.md`/`CLAUDE.md` 提取人设(复用 gzh-longform `references/persona-reading.md` 字段表:人设口吻 / 目标人群 / 定位 / 禁用词 / 创作规范)。关键字段缺失 → 停下问用户。**同时读目的仓库已发口播稿/文案**,校准品牌风格。

### 第 1 步 接收选题/素材

- **backlog 取**:扫目的仓库 `Topics/backlog.md`,列待做条目让用户选。
- **当场给**:用户提供主题/文本/链接,整理成选题结构。
- **素材要求**:一手素材(原文/官方信息)当骨架,二手转述只作补充;有实锤数字/事实必须用。

### 第 2 步 内容设计(先审"说什么",再写"怎么说")

**写稿前先过内容审核**,输出给用户确认:
- [ ] 选题核心框架是否完整(如"不可能三角"这类核心概念是否贯穿全文,没被表达改动弄丢)
- [ ] 论点与框架的映射关系是否讲清(每个分点要挂回核心框架)
- [ ] 一手素材实锤是否用上(具体工具名/版本/官方动作)
- [ ] 事实 vs 举例是否分清(虚构数字要标"假设/比如",不当真实统计)
- [ ] 结构:开头痛点 → 分点 → 正确姿势 → 佐证 → 金句收尾

**内容确认后才生成草稿**。结构:
- **标题**:见「标题规范」
- **开头钩子**:一句**具象事实 + 悬念问题**(不用"有个词叫 XX"的概念引入)
- **正文**:分段,一段一个意思;对话感 + 口语节奏;专业词第一次出现给大白话(不降级消费级词)
- **结尾**:收尾金句 + 互动钩子(按目的仓库惯例,如"评论区聊聊")

### 第 3 步 生成草稿(带节奏标注)

草稿必须带**节奏标注**(念稿人的"演奏谱"),精简体系:
- `(停顿)` 换气留白 / `(停2秒)` 长停顿抛问题后
- `(放慢)` / `(加快)` 语速
- `(加重)` 重音关键结论 / `(轻声)` 低语悬念
- `(笑)` / `(反问)` 语气表情
- `…` 拖长音 / `↗` `↘` 升降调

口语化硬标准:**读一遍转文字,要像平时说话**——允许填充词(这个/那个/然后/其实/所以说)、冗余、补述;杀书面缩写(真不是/即/亦)、杀伪专业词(书面语伪装成概念),真专业词带解释保留。

### 第 4 步 逐轮调稿(用户主导)

- 每轮记录(调稿记录文件,见「调稿记录格式」):用户要求**原话** / 改动点 / 原因
- **节奏**:出一版"定稿感"完整稿让用户对整篇开火,不要反复抛候选选择题
- 用户说"OK/确认"(或"已录音")才算定稿
- 改表达不改骨架;内容审核(第 2 步)在调稿中发现问题随时补做

### 第 5 步 定版校验

- 按目标时长核对字数(200-260 字/分钟)
- 定版前跑目的仓库标点全角化脚本(punct_normalize 类)+ 复检
- 存 `OUTPUT_DIR/script.md`,frontmatter:`title` / `topic` / `duration` / `wordcount` / `status: draft`

## 标题规范(核心经验)

1. **先读目的仓库已发内容的标题**,校准风格再挖;不要随手写
2. **纯悬念问句 > 给半个答案**:「问题出在哪?」强于「你缺的不是 X」——答案全留正文
3. **禁营销腔**:「警告!」「你知道吗」与冷静陈述者人设冲突;痛点场景 + 人话动作 + 冷静
4. 用标题公式库(如 dbs-xhs-title)挖题时,公式结构可留,表达换成目的仓库腔

## 调稿记录格式

调稿期间维护一份记录文件(如 `docs/口播稿调稿记录-<主题>.md`),每轮:

```
### 第 N 轮(日期)
- 状态:完成 / 进行中
- 用户要求(原话):<引用原话>
- 改动点:<改了哪>
- 原因(推断):<为什么这么改>
```

草稿每版存档(`v1`/`v2`/...),供版本对比。调稿结束把各轮经验提炼进 `references/tuning-lessons.md`。
